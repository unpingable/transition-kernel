# Continuation trajectory — the two-step AG-on-AG specimen (GAP-2 C4)

Not new mechanism — the C3 continuation enforce mechanism **walked as a trajectory**. Generated by
`generate.py` over the real `la_cli` + `transition-cli` and the real `agent_gov` orchestration
(`transition_enforce` + `continuation_enforce`). Each bundle holds the durable `effects.jsonl` (the
Stage 3 effect chains), the `continuation.jsonl` (the durable continuation burn ledger), a `result.json`,
and a `reconstruct.json` (both ledgers replayed).

```
step 1:  governed effect executes (initial delegation; no continuation required yet)
         -> composed Stage 3c snapshot + terminal outcome recorded
bridge:  request next step -> grant issued -> durable BURN before the next transition gate
step 2:  the next governed action reaches the transition gate ONLY because the grant was burned
replay:  reconstructs both steps and the continuation bridge
```

| Bundle | What it shows | Replay |
|---|---|---|
| `two-step-success/` | one bounded step, then exactly one *earned* next step via a single-use grant | both effects `consumed_effect_succeeded`; continuation `admitted_to_transition` |
| `no-grant-refused/` | step 2 proposed **outside the slice** (scope expansion) → office refuses → no grant → step 2 never reaches the transition gate (legacy unreachable) | only step 1 effect; continuation ledger empty (nothing burned) |
| `burned-but-effect-refused/` | grant burned, but step 2's effect gate refuses (eligibility recombination) → the grant **remains spent**; re-presenting it is `already_consumed` | step 1 effect only; continuation `admitted_to_transition` (spent) |

> **Claim:** a supervised agent executed a bounded governed step, earned exactly one further governed step
> through a single-use continuation grant, and the full two-step trajectory is replay-legible.

Load-bearing invariants the specimen walks:

- **The grant gates *entry* to step 2's transition gate, not the effect itself.** The effect still crosses
  the normal LA-consume + bounded-effect chain. `generate.py` runs the step-2 chain only on an admitted
  burn — exactly as the C3 supervisor `enforce` branch does.
- **A grant authorizes one next-step *attempt*, not one successful effect** (`burned-but-effect-refused`):
  the burn is spent even when the downstream effect gate refuses. No retry-by-renarration — re-presenting
  the same grant is `already_consumed`.
- **No grant ⇒ no next step** (`no-grant-refused`): the legacy continuation path is structurally
  unreachable; step 2 leaves no consume or effect.

Regenerate with `python3 generate.py` (requires `la_cli` + `transition-cli` built and `agent_gov`
importable). Running it *is* the walk: every trajectory invariant is asserted, so a regression fails loudly
rather than silently rewriting the committed specimen. The `sandbox/` markers are gitignored — the durable
ledgers are the specimen, not the environment-specific marker paths.
